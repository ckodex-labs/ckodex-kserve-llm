# Open Loops — ckodex-kserve-llm-operator

Structured tracker for incomplete work, pending decisions, and tracked deferrals.
Each entry carries an ID, status, priority, and owner note.

Status values: `open` | `in-progress` | `blocked` | `deferred` | `done`
Priority: `P0` (release-blocking) | `P1` (GA-quality) | `P2` (improvement) | `P3` (nice-to-have)

## CI/CD

### L-CI-001 — Migrate GHA workflows to `dagger call`
- **Status:** open
- **Priority:** P2
- **Context:** ADR-008 adds the Dagger Module (`dagger.json` + `dagger/main.go`).
  GHA currently calls `go run ./ci/main.go`. Once the module is proven stable
  (at least 3 passing GHA runs with `dagger develop` + `dagger call`), the
  `.github/workflows/ci.yml` "Run Dagger Pipeline" step should change from:
  ```yaml
  run: go run ./ci/main.go
  ```
  to:
  ```yaml
  run: |
    dagger develop
    dagger call all --source=.
  ```
  And the release workflow's image-release step should delegate to `dagger call publish`.
- **Blockers:** Needs GHA runner testing for Dagger engine startup time and
  OIDC/secret injection in module context.
- **Reference:** ADR-008, `.github/workflows/ci.yml:65`

## Supply Chain

### L-SC-001 — Generate `dagger develop` output in CI and commit `dagger/internal/`
- **Status:** open
- **Priority:** P1
- **Context:** `dagger/internal/dagger/` is generated by `dagger develop`. It is
  currently not committed (generated code). Two options:
  1. Commit `dagger/internal/` (common for Dagger modules) — always available,
     no develop step in CI.
  2. Run `dagger develop` in CI before `dagger call` — adds ~10s startup.
  Recommended: commit generated code (option 1) to keep CI fast and reproducible.
  This requires running `dagger develop` locally and committing the output.
- **Note:** Sandbox filesystem restrictions blocked `dagger develop` in this
  session. Must be run outside the sandbox (native terminal, full repo access).
  Command: `cd <repo-root> && dagger develop && git add dagger/internal/ && git commit -m "chore: generate dagger module SDK"`
- **Reference:** `dagger/go.mod`, `docs/adr/008-dagger-module.md`
