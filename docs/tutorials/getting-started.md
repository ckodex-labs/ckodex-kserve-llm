# Getting started with the operator

This tutorial guides you through installing the CKodex KServe LLM Operator and running your first inference query in under five minutes.

You will install the custom resource definitions, deploy the operator controller manager with Helm, submit an inference service manifest, and send an OpenAI-compatible chat completion request.

## Prerequisites

Before starting, confirm that your workstation has:

- A Kubernetes cluster (version 1.30 or newer, such as KIND or Minikube)
- `kubectl` configured to communicate with your cluster
- `helm` (version 3.12 or newer)
- `curl` and `jq`

Verify cluster access:

```bash
kubectl cluster-info
```

## Step 1: Install custom resource definitions

Install the operator custom resource definitions (CRDs). These establish the schema for `LLMInferenceService`, `AIPack`, `MultimodalInferenceService`, and supporting kinds:

```bash
kubectl apply -f config/crd/serving.ckodex.com_llminferenceservices.yaml
kubectl apply -f config/crd/serving.ckodex.com_aipacks.yaml
kubectl apply -f config/crd/serving.ckodex.com_multimodalinferenceservices.yaml
kubectl apply -f config/crd/serving.ckodex.com_agents.yaml
kubectl apply -f config/crd/serving.ckodex.com_localmodelcaches.yaml
kubectl apply -f config/crd/serving.ckodex.com_modelservingprofiles.yaml
```

Confirm that the CRDs are registered:

```bash
kubectl get crd | grep ckodex.com
```

You should see `llminferenceservices.serving.ckodex.com` in the output.

## Step 2: Deploy the operator controller manager

Deploy the operator into the `ckodex-system` namespace using the canonical Helm chart in `deploy/helm`:

```bash
helm upgrade --install ckodex-operator deploy/helm \
  --namespace ckodex-system \
  --create-namespace \
  --wait
```

Verify that the operator pod is running and ready:

```bash
kubectl get pods -n ckodex-system -l control-plane=controller-manager
```

Inspect the operator startup log to confirm leader election and reconciler activation:

```bash
kubectl logs -n ckodex-system -l control-plane=controller-manager -c manager --tail=20
```

## Step 3: Deploy your first language model service

Create a file named `first-model.yaml` defining a lightweight specimen inference service:

```yaml
apiVersion: serving.ckodex.com/v1
kind: LLMInferenceService
metadata:
  name: quickstart-llm
  namespace: default
spec:
  model:
    name: quickstart-specimen
    uri: hf://tiny-random/kimi-k3.1-pro
  replicas: 1
  template:
    spec:
      containers:
        - name: vllm
          image: vllm/vllm-openai:v0.33.0@sha256:d825baf9ce4b1b6bfc5ecc7b79880c7e6748c65a72d697ce3d47607aafa84c6e
          resources:
            requests:
              cpu: "2"
              memory: 4Gi
            limits:
              cpu: "2"
              memory: 4Gi
```

Apply the manifest to your cluster:

```bash
kubectl apply -f first-model.yaml
```

## Step 4: Verify service reconciliation and readiness

The operator admission pipeline evaluates the manifest, passes data and model admission, and provisions the underlying Deployment, Service, and HTTPRoute.

Watch the status of the custom resource:

```bash
kubectl get llminferenceservice quickstart-llm -n default -w
```

You will see the lifecycle state transition through `ADMITTED`, `PROVISIONING`, `WARMING`, and finally `READY`.

Check the underlying pod status:

```bash
kubectl get pods -l app.kubernetes.io/name=quickstart-llm -n default
```

Once the pod reports `1/1 Running`, describe the custom resource to inspect status conditions:

```bash
kubectl describe llminferenceservice quickstart-llm -n default
```

The conditions table shows `Ready: True` with reason `ServiceReady`.

## Step 5: Run your first inference query

Forward local port 8000 to the model service:

```bash
kubectl port-forward svc/quickstart-llm 8000:8000 -n default &
PORT_FORWARD_PID=$!
```

Send an OpenAI-compatible chat completion request with `curl`:

```bash
curl -s -X POST http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "quickstart-specimen",
    "messages": [
      {"role": "system", "content": "You are a helpful assistant."},
      {"role": "user", "content": "Hello, explain what an inference operator does in one sentence."}
    ],
    "max_tokens": 64
  }' | jq .
```

You receive a JSON response containing `choices[0].message.content` generated by the model engine.

Stop the background port forward:

```bash
kill $PORT_FORWARD_PID
```

## Step 6: Clean up resources

To delete the inference service:

```bash
kubectl delete -f first-model.yaml
```

To remove the operator and custom resources completely:

```bash
helm uninstall ckodex-operator -n ckodex-system
kubectl delete namespace ckodex-system
```

## What you learned

In this tutorial, you:

1. Registered the operator custom resource definitions.
2. Deployed the controller manager via Helm.
3. Created an `LLMInferenceService` custom resource.
4. Monitored the lifecycle transitions to `READY`.
5. Queried the running model over the OpenAI-compatible `/v1/chat/completions` API.
